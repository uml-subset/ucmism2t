module ucmism2t::templates::target::doc::puUtilityDoc

Module contains utility templates for generating PlantUML diagram code. These templates are shared between pu_classDiagram and pu_dataTypeDiagram and cover: - Diagram options (skinparam settings) - Hyperlink construction (pu_link, pu_attributeLink, pu_linkWithLabel) - Classifier node definitions (pu_itemDefinition, pu_classifierNameWithLabel) - Aggregation kind symbols (pu_aggregationKind) - Data type notation stereotypes (pu_dataTypeNotation) - Generation message header (pu_generationMessageDoc) - Attribute type with hyperlink (pu_typeWithLink, pu_internalLinkType) - Internal hyperlinks for named elements (pu_internalLink) - Conditional qualified class name (e_conditionalQualifiedClassName) - Whitespace removal utility (e_removeWhitespace)
Metamodels http://www.eclipse.org/uml2/5.0.0/UML, http://www.eclipse.org/uml2/5.0.0/Types, http://www.eclipse.org/uml2/5.0.0/UML/Profile/Standard

[template public pu_options(anEObject : ecore::EObject)]
  ' HD display aspect ratio 16:9
  ' hyperlinkColor and pathHoverColor do not seem to work with class diagrams
  ' working approach: colors per item
  ' default font size for class names is 14
  
  hide circle
  hide empty members
  'scale 2
  scale 0.9
  
  skinparam {
    ArrowThickness 1.5
    MinClassWidth 150
  }
  
  skinparam legend {
    BackgroundColor white
    FontSize 10
  }
  
  skinparam note {
    BackgroundColor white
  }
  
  skinparam class {
    ArrowColor #404040
    BorderColor #404040
  }
  
  skinparam package {
    FontColor lightgrey
    BorderColor lightgrey
  }[/template]

template public pu_typeWithLink

[template public pu_typeWithLink(aType : uml::Type)]
Generates an attribute type name with an optional hyperlink for use in class body attribute lines in the diagram. When the type is not a UML primitive type, the name is rendered in blue and followed by a three-bracket attribute hyperlink pointing to the type's diagram page. When the type is a primitive, only the plain name is emitted. The multi-line AQL expression inside the single block is wrapped purely for source readability; it produces a single unbroken output line, avoiding the Acceleo prefix-repetition issue that would arise if the call were split across multiple template lines.
