module ucmism2t::queries::associationQuery

Module contains queries with a UML association as receiver. This includes queries for navigating association ends (owned end, other end, source class, target class), computing short association names, and testing whether an association belongs to a diagram subset. The association direction convention used throughout this module and the diagram templates is: ownedEnd = the source (subject) end, owned by the association otherEnd = the target (object) end, owned by the source class Note: Queries that find associations starting from a class are in classQuery, since their receiver is a UML class. Related modules: - classQuery: queries with a UML class as receiver, including queries that find associations of a class - propertyQuery: queries with a UML property as receiver, since association ends are properties in UML
Metamodels http://www.eclipse.org/uml2/5.0.0/UML, http://www.eclipse.org/uml2/5.0.0/Types, http://www.eclipse.org/uml2/5.0.0/UML/Profile/Standard

query public u_isAssociationInSubset

[query public u_isAssociationInSubset(anAssociation : uml::Association, aClass : uml::Class, aSubsetPackage : uml::Package) : Boolean = ...]
Returns true if the given association should be shown in a context diagram for the given class, according to the current subset configuration. An association is included when any of the following holds: (a) the property 'includeAllItems' is true, meaning no subset filtering is active; (b) aSubsetPackage is not null (a profile subset is active) and both the source and target class of the association are members of that package's dependency-defined supplier classes, checked by object identity via u_childDependencySupplierClasses; (c) aSubsetPackage is null and the property-file-based subset applies: the other end class name is in u_subsetAllClasses relative to the focal class aClass. The focal class aClass is always assumed to be in the subset (it is the subject of the diagram), so only the other end needs to be tested in the property-file case. Note: Both u_ownedEndClass() and u_otherEndClass() assume both association ends are typed by uml::Class. Associations targeting DataTypes are excluded upstream by u_associations(). This query centralises the subset-filter condition used in: - pu_classDiagram (focal class associations) - pu_superClass (inherited superclass associations)

[query public u_isAssociationInSubset(
  anAssociation : uml::Association,
  aClass : uml::Class,
  aSubsetPackage : uml::Package) : Boolean =
  (aSubsetPackage <> null
    and aSubsetPackage.u_childDependencySupplierClasses()
          ->includes(anAssociation.u_ownedEndClass())
    and aSubsetPackage.u_childDependencySupplierClasses()
          ->includes(anAssociation.u_otherEndClass()))
  or (aSubsetPackage = null
      and ('includeAllItems'.isPropertyTrue()
        or (aClass = anAssociation.u_ownedEndClass()
            and aClass.u_subsetAllClasses()
                  ->includes(anAssociation.u_otherEndClass().name))
        or (aClass <> anAssociation.u_ownedEndClass()
            and aClass.u_subsetAllClasses()
                  ->includes(anAssociation.u_ownedEndClass().name))))
/]

[query public u_shortAssociationName(
  anAssociation : uml::Association) : String =
  let n : String = anAssociation.name in
  if n = ''
  then 'WARNING: no association name!'
  else
    if n.contains('_')
    then
      let nameAfterFirst : String =
        n.substring(n.index('_') + 1)
      in
      if nameAfterFirst.contains('_')
      then nameAfterFirst.substring(1, nameAfterFirst.index('_') - 1)
      else 'WARNING: association name has only one underscore!' + n
      endif
    else n
    endif
  endif
/]
